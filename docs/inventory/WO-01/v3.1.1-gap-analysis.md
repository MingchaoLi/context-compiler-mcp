## Current behavior that conflicts with the target if reused unchanged

1. **Fixed recent-N selection.** `assembleContext` selects a caller-provided count
   of recent turns. Treating this as the future hot Raw boundary would violate the
   target Raw Frontier/pressure model.
2. **Generic action terminology.** Treating public Experience Ledger `ACTION` and
   `OUTCOME` entries as the formal execution lifecycle would erase required start,
   attempt, verification, interruption, idempotency, and recovery boundaries.
3. **Session-scoped identity.** Session/turn keys cannot substitute for
   target namespace/stream identity or a shadow-isolated revision domain.
4. **Public low-level mutation.** Continuing to expose stores and reducer entry
   points as the primary integration surface would leave writer authority ambiguous.
5. **Distributed schema ownership.** Extending each store independently would make
   cross-substrate crash invariants harder to prove and recover.

## Unknown because it is outside WO-01 evidence

- Which host will ultimately own Main Agent invocation, arbitrary tool execution,
  external delivery, and human-interrupt transport.
- Whether any external host already has operation, outbox, or compaction primitives
  worth adapting. WO-01 was prohibited from reading sibling host repositories.
- Production scale, concurrency, and migration constraints beyond the checked-in
  tests and official evidence manifests.

These unknowns do not block the next Core work order. WO-02 can define the stable
authority boundary without choosing a host or provider.

## Direct inputs to the next work orders

### WO-02

- Define one authoritative mutation path per current substrate before adding new
  concepts.
- Keep host responsibilities outside the Core: agent invocation, arbitrary tool
  execution, transport delivery, UI, packaging, and provider choice.
- Preserve current observable behavior while wrapping low-level writers behind
  stable commands and making transaction ownership explicit.
- Treat `DSH_HOME` as a bounded compatibility adapter, not a dependency direction.

### WO-03A

- Reuse append-only raw evidence, per-session sequencing, State revision,
  `source_key`, and preparation fingerprints as primitives—not as the final shared
  revision substrate.
- Specify namespace, stream identity, revision ownership, Raw Frontier position,
  and compare-and-commit behavior before implementing Takeover or Facts.
- Define migrations and replay invariants for the current SQLite stores rather than
  silently assigning a new meaning to `session_id`, `turn_id`, or State revision.

## Classification

The current architecture is **partially coupled**: its Core is provider-independent
and much of the persistence is reusable, but mutation authority, runtime identity,
and execution lifecycle boundaries are not yet strong enough for the v3.1.1 target.
